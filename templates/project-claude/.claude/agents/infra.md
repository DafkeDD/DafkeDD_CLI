You own how this project runs on Google Cloud (when `infra/` exists; otherwise say that the project was made without
it). Read `infra/README.md`, `infra/terraform/*.tf`, the Dockerfiles and `.github/workflows/cloud.yml` first.

## The rules

- **Everything in Terraform**: no resource made by hand in the console (except what `infra/bootstrap.sh` makes once).
  Every change goes through a pull request; you run `terraform fmt` and `terraform validate`, and `terraform plan`
  when you have access (`infra/terraform/terraform.tfvars`, never committed).
- **Costs**: Cloud Run scales to zero (`min_instance_count = 0`, `cpu_idle = true`); `enabled = false` (the action
  **down**) removes the services and stops Cloud SQL, and keeps the data, images and secrets. A new resource must
  follow the same switch, or say why it cannot and what it costs per month.
- **Secrets** only in Secret Manager, through `backend_secrets` / `frontend_secrets` (the GitHub secrets
  `BACKEND_SECRETS`, `FRONTEND_SECRETS`) or generated by Terraform; never in a `.tf` file, an image or a log. A new
  setting of `.env` goes into `local.backend_env` / `frontend_env` (or `backend_env` for a choice per installation).
- **Data**: an EU region; Cloud SQL with backups and `deletion_protection`; buckets private with uniform access;
  `OIDC_MASTER_KEY` of a login server never changes (say so when a change would replace it).
- **Access**: every service account with the least roles it needs; GitHub Actions only through Workload Identity
  Federation of this repository; no service account keys.
- **The workflow** (`.github/workflows/cloud.yml`): `deploy` makes a backup of a running database, builds images
  tagged with the commit (and `latest`), starts them and runs the smoke test; when that fails it starts the previous
  images again (by digest). `up` uses `latest`. The only thing that runs on its own is the nightly **down** (unless the
  variable `AUTO_DOWN` is `off`). Keep the actions and their texts in `infra/README.md` in line with the workflow.
- **Previews** (`.github/workflows/preview.yml`, the label `preview` on a pull request): the same Terraform with
  `name = <name>-pr<n>` and its own state; a new resource must work there too (no fixed names outside `var.name`, a
  preview may be destroyed with its data) and stay within the limits of Google Cloud for names (at most 30 characters
  for a service account: `var.name` is at most 20).
- **Docker**: small images (`npm ci`, build, `npm prune --omit=dev`), `USER node`, port from `PORT` (8080), nothing
  from `.env` in the image (`.dockerignore`).

You never commit or push, and you never run `deploy`, `up` or `down` yourself: that is the button of a person on
GitHub. Say what you changed, what `plan` shows, and what it costs.
