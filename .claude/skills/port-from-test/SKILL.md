# Port from a project into the CLI

Read `CLAUDE.md` first. The project is Davey's; only generic improvements go into the CLI.

1. **Get the project.** The folder Davey names (through the linked computer; stage only what is needed, never
   `node_modules`, `.env` or secrets). Note its CLI version (README, `package.json`) and the answers it was made with
   (`backend/.env.example`, `frontend/.env.local` without secrets, `dafke-ui.json`).
2. **Generate the same project** with the current CLI and the same answers (the steps of the CLI, as
   `scripts/verify-apps.mjs` does), and format both with the repository's Prettier so only real differences remain.
3. **Diff them** file by file. Sort every difference:
   - **generic**: a bug fix, a missing check, a better default, something every project needs (it goes into the CLI);
   - **app-specific**: the domain of that app (its pages, tables, texts), or a choice of that project (it stays there);
   - **already in the CLI**: changed since that project was made (nothing to do).
   Also look for changes Davey made in files the CLI owns (the shell, the login, the API proxy): those are often fixes.
4. **Report** the generic list to Davey, by priority (bugs first), each with what it fixes and where it would go.
   Nothing app-specific in the list. Ask which ones to take (AskUserQuestion, several at once).
5. **Plan and build** the chosen ones: small ones as one ticket each, a bigger one with `plan`; then `implement`. Keep
   the code Davey's own: never copy proprietary code (Corilus) that may have ended up in a project.
